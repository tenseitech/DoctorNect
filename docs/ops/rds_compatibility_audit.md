## 2. Dashboard-Only Settings (Do Not Carry Over to RDS)

The following configurations live strictly in the Supabase Cloud web dashboard and have no representation in SQL migrations:
1. **Firebase Third-Party Auth Integration:** Supabase dashboard decodes Firebase JWTs directly. *On RDS Option A:* The Node.js Auth Gateway in front of PostgREST verifies Firebase ID tokens and mints short-lived PostgREST JWTs.
2. **Database Webhooks:** Supabase webhooks calling HTTP endpoints on insert/update. *On RDS:* Replaced by direct application events or AWS SNS/SQS.
3. **Realtime Settings & Quotas:** WebSocket limits and exposed tables. *On RDS:* Replaced by Flutter adaptive polling (`streamTable`) with change detection.
4. **API Exposed Schemas & Max Rows:** PostgREST settings in Supabase dashboard. *On RDS:* Configured explicitly via `PGRST_DB_SCHEMAS=public` and `PGRST_DB_MAX_ROWS=1000` environment variables in PostgREST container.
5. **Connection Pooler (Supavisor):** Port 6543 pooler. *On RDS:* PostgREST manages its own internal connection pool; RDS Proxy optional for high concurrency.
