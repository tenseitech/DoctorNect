## `review_public` grants (migration)

- **`GRANT SELECT, INSERT, UPDATE, DELETE ON public.review_public TO service_role`**
- **Why:** After owner change, `fn_sync_review_aggregates` runs as `service_role` and must maintain `review_public` rows under FORCE RLS on source tables.
- **Anon/authenticated access:** Unchanged by this migration; anon SELECT remains via RLS policies + bootstrap `04` grants, not table-wide anon DML.

## FAIL criteria (none observed in design)

- No function owned by `service_role` retains EXECUTE for `anon` or `PUBLIC` on the four targets above.
- Callable `anon`/`PUBLIC` paths that combined with BYPASSRLS would skip RLS: **none** for these four (private helpers revoked from anon; trigger function not granted to clients).

## Minimal schema grant (root cause)

- **`GRANT CREATE ON SCHEMA private TO service_role`** — required so `ALTER FUNCTION ... OWNER TO service_role` succeeds for `private.*` helpers.
- **`GRANT CREATE ON SCHEMA public TO service_role`** — same PostgreSQL rule for `public.fn_sync_review_aggregates()` (trigger).
- Does **not** grant `doctornect_admin` BYPASSRLS/superuser; migrator only runs `ALTER … OWNER` as existing function owner.
- Migrator (`doctornect_admin`) must own functions (normal migration path) and be able to grant role membership to `service_role` (bootstrap `01_roles_and_extensions.sql`).
