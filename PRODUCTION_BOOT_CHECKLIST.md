# Production boot checklist

Since round 2 the backend boot assertions run on every deployed cold start (they used to be
skipped in "legacy Firestore" mode). A missing or wrong value now stops the Function or the gateway
from starting. Validate an env file before every deploy:

```powershell
npm run check:boot-env -- backend/functions/.env.production --target=functions
npm run check:boot-env -- path\to\gateway.env --target=gateway --app-env=production
```

The checker runs the real boot assertion code (`backend/functions/src/db/assert_app_env.js`,
`production_otp_guard.js`, `services/api-gateway/src/assert_production_config.js`) against only
the variables in the file, in a simulated Cloud Functions runtime, and adds the checklist-only items
below. It never prints values: every value from the file is redacted from its output. Exit code 1
means at least one FAIL.

Legend. **Where**: `SM` = Firebase Secret Manager (`firebase functions:secrets:set NAME`), bound
with `defineSecret`. Never put these in a `.env` file. `ENV` = plain Functions env
(`backend/functions/.env.<project>` generated by `npm run materialize:functions-env`). `ECS` = gateway
task definition (secrets from AWS Secrets Manager, plain values as environment).
**Boot**: `yes` = startup fails without it, `call` = the first call that needs it fails, `check` =
reported by `check:boot-env` only.

## 1. Cloud Functions (backend/functions)

### Environment selection and data plane

| Variable | Staging | Production | Format | Where | Boot | Error when missing / wrong |
|---|---|---|---|---|---|---|
| `APP_ENV` | `staging` | `production` | enum | ENV | yes | wrong value selects the wrong database and bucket |
| `FIRESTORE_FORBIDDEN` | `1` recommended | **`1` required** | `1` | ENV | yes | `[AppEnv] APP_ENV=production requires FIRESTORE_FORBIDDEN=1 (Firestore is no longer used).` |
| `PROD_GATEWAY_URL` | unset | required | `https://` URL of the RDS auth gateway, not `*.supabase.co`, not the staging URL | ENV | yes | `[AppEnv] APP_ENV=production requires PROD_GATEWAY_URL, PROD_GATEWAY_SERVICE_KEY. ...` / `PROD_GATEWAY_URL points at supabase.co ...` / `must not equal STAGING_SUPABASE_URL` |
| `PROD_GATEWAY_SERVICE_KEY` | unset | required | 32+ chars, equals gateway `SERVICE_ROLE_KEY` | SM | yes | same as above |
| `STAGING_SUPABASE_URL` (or `SUPABASE_URL`) | required | unset (or demo plane only) | `https://<ref>.supabase.co` | ENV | yes (staging) | `[AppEnv] APP_ENV=staging requires STAGING_SUPABASE_URL (or SUPABASE_URL) ... for Postgres access.` |
| `SUPABASE_SERVICE_ROLE_KEY` (or `STAGING_SUPABASE_SERVICE_ROLE_KEY`) | required | unset | Supabase service key | SM | yes (staging) | same as above |
| `DATABASE_URL` / `PROD_RDS_DATABASE_URL` | unset | only when the Functions use the direct pg pool | `postgresql://...?sslmode=verify-full` | SM | check | `cutover completeness ... DATABASE_URL` (checker WARN) |
| `SKIP_APP_ENV_DB_ASSERT` | unset | **must be unset** (ignored in deployed production) | `true` | ENV | - | skips the boot asserts outside deployed production |

### Demo / reviewer accounts (optional; see docs/DEMO_ACCOUNTS.md)

The five demo numbers, roles and Firebase UIDs are fixed in code (`scripts/lib/demo_accounts.js`).
They always use the staging plane; real numbers always use RDS.

| Variable | Production | Format | Where | Boot | Error |
|---|---|---|---|---|---|
| `REVIEWER_OTP_ENABLED` | `true` only while a store review runs | bool | ENV | yes | if on: needs a future `REVIEW_ACCESS_UNTIL` and `DEMO_SUPABASE_URL`: `reviewer OTP enabled but misconfigured: ...` |
| `REVIEW_ACCESS_UNTIL` | future ISO 8601 instant | `2026-12-31T23:59:59Z` | ENV | yes if reviewer on | `... REVIEW_ACCESS_UNTIL (future ISO timestamp)` |
| `REVIEW_FIXED_OTP` | the demo OTP (`000000`) | 6 digits | **SM** | yes (OTP functions) | `REVIEWER_OTP_ENABLED=true but the REVIEW_FIXED_OTP secret is missing in verifyUserRegistrationOtp`; as plain env with reviewer off: `REVIEW_FIXED_OTP must be a Firebase secret` |
| `DEMO_SUPABASE_URL` | staging Supabase URL used for demo users | URL | ENV | yes if reviewer on | `... DEMO_SUPABASE_URL` |
| `DEMO_SUPABASE_SERVICE_ROLE_KEY` | staging service key | secret | **SM** | call | demo logins fail (`unavailable`) |
| `RAZORPAY_TEST_KEY_ID` / `RAZORPAY_TEST_KEY_SECRET` | optional Razorpay test keys for demo accounts | `rzp_test_...` / secret | ENV / **SM** | call | demo payment: `Payments are disabled for demo accounts.` (live keys are never used for demo accounts) |
| `DEMO_REAL_ROUTING_ENABLED`, `DEMO_FIREBASE_UID_ALLOWLIST` | optional: only for EXTRA demo UIDs | `1` / list | ENV | - | the five built-in demo UIDs route to staging without them |
| `REVIEW_*_PHONES`, `REVIEW_TEST_NUMBERS`, `DEMO_PHONE_NUMBERS`, `DEMO_FIXED_OTP` | obsolete, ignored | - | - | - | `check:boot-env` warns; remove them |
| `OTP_TEST_MODE`, `DEMO_PHONE_*`, `GOOGLE_PLAY_REVIEW_PHONE`, `TEST_PHONE_NUMBER` | **must be unset** | - | - | yes | `Production OTP safety check failed for medibond-45fad: OTP_TEST_MODE is enabled; demo phone env configured (...)` |

## 2. API gateway (services/api-gateway, ECS)

`assert_production_config.js` blocks startup when `APP_ENV=production` or `NODE_ENV=production`:
`[Auth Gateway] Production startup blocked — invalid or missing: <list>`.

| Variable | Staging | Production | Format | Where | Boot | Error |
|---|---|---|---|---|---|---|
| `APP_ENV` / `NODE_ENV` | `staging` | `production` | enum | ECS env | - | production asserts are skipped if neither is production |
| `PGRST_URL` | local PostgREST | PostgREST over RDS (`sslmode=verify-full`, RDS CA) | URL | ECS env | check | defaults to `http://127.0.0.1:3001` |
| `PGRST_JWT_SECRET` | 32+ chars | 32+ chars, not the default | secret | AWS SM | yes | `PGRST_JWT_SECRET (min 32 chars, not default)` |
| `PGRST_JWT_AUD` | `authenticated` | `authenticated` | string | ECS env | - | - |
| `ANON_KEY` | random | random, not `doctornect-anon-public-key` | secret | AWS SM | yes | `ANON_KEY (must not use default placeholder)` |
| `SERVICE_ROLE_KEY` | 32+ chars | 32+ chars (= Functions `PROD_GATEWAY_SERVICE_KEY`) | secret | AWS SM | yes | `SERVICE_ROLE_KEY (min 32 chars)` |
| `FIREBASE_PROJECT_ID` | project id | `medibond-45fad` | string | ECS env | check | token audience mismatch → 401 |
| `FIREBASE_REVOCATION_CHECK` | `true` | must not be `false` | bool | ECS env | check | revoked tokens accepted |
| `CORS_ALLOWED_ORIGINS` | staging origins | prod origins | comma list | ECS env | check | defaults to doctornect.com origins |
| `TRUSTED_PROXY_HOPS` | 1 | 1 (ALB) | int | ECS env | check | spoofable client IP |
| `DEMO_REAL_ROUTING_ENABLED` | - | `1` only with demo plane | `1` | ECS env | call | - |
| `DEMO_PGRST_URL`, `DEMO_PGRST_JWT_SECRET`, `DEMO_PGRST_JWT_AUD` | - | required whenever demo accounts are used (the five demo UIDs always route here) | URL / secret / list | ECS | call | demo users get `503 Demo data plane is not configured.` |
| `RATE_LIMIT_*`, `ANON_RATE_LIMIT_*`, `ANON_MAX_ROWS`, `MAX_BODY_SIZE_BYTES`, `FAILED_SERVICE_KEY_*` | defaults | defaults | int | ECS env | - | defaults apply |

## 3. Images to rebuild before production boot

1. API gateway image (current `services/api-gateway`).
2. PostgREST image with the RDS CA bundle baked in and `PGRST_DB_URI=...?sslmode=verify-full&sslrootcert=/etc/ssl/rds/global-bundle.pem`.
3. Cloud Functions: `firebase deploy --only functions` after `npm run materialize:functions-env` and `npm run check:boot-env`.
